title: "Frog Nano: 대형 모델 증류 없이 하네스와 온라인 RL만으로 4B 코딩 에이전트 만들기"
---

요즘은 뛰어난 모델을 만들기 위해서는 증류(Distillation)가 필수라는 인식이 있습니다. 특히 소형 모델일수록 증류나 고품질 SFT 데이터셋이 필수라는 인식이 있죠. 하지만 소형 모델일수록 하네스와 강화학습(RL)이 가장 중요하다고 말하는 논문이 있습니다.

Microsoft Research 팀이 발표한 논문 "Frog Nano: Training a 4B Coding Agent via Online Task Synthesis"는 대형 모델의 궤적을 베끼는 증류식 사전 웜업(SFT) 없이, 하네스와 RL만으로 4B 모델을 거대 모델 수준의 에이전트로 키워낸 결과를 보여줍니다. 그 핵심을 정리해 드립니다.

1. 학습 알고리즘 이전에 인터페이스(하네스)가 먼저다 (8.3% -> 37.2%)

기존 표준 에이전트 하네스(R2E-Gym) 환경에서 베이스 모델인 Qwen3.5-4B를 돌렸을 때, 모델은 제출 프로토콜을 다루지 못해 전체 시도의 96%가 턴 제한에 걸려 타임아웃되었습니다. 해결률은 고작 8.3%에 불과했습니다.

연구진은 가중치 학습 전에 인터페이스부터 Claude Code 스타일의 경량 하네스(LEAF)로 바꿨습니다.

- 5개의 직관적인 도구만 제공: read, write, edit, glob, bash.

- 자연스러운 종료 규칙: 복잡한 제출 액션 대신 도구 호출이 없는 텍스트 응답을 완료 신호로 간주.

가중치를 단 1스텝도 튜닝하지 않고 인터페이스만 바꿨을 뿐인데, 성공률이 8.3%에서 37.2%로 무려 4배 이상(+28.9%p) 올랐습니다.

반면 수백 B 크기의 거대 모델(MiniMax-M2.5)은 두 하네스 모두 66.5%로 인터페이스에 영향을 받지 않았습니다. 대형 모델은 난해한 인터페이스도 본인의 지능으로 뚫어내지만, 소형 모델에게는 복잡한 하네스 자체가 지능을 갉아먹는 치명적인 병목이었던 셈입니다.

2. 정적인 데이터셋 대신 난이도 맞춤형 합성 (TaskPilot)

출발선(37.2%)에 선 뒤, 성능을 61.5%까지 끌어올린 엔진은 순수 강화학습(RL)이었습니다.

여기서 핵심은 고정된 실제 이슈 데이터를 쓰는 대신, 현재 모델의 눈높이에 맞춰 실시간으로 가상 문제를 빚어내는 온라인 태스크 합성(TaskPilot)입니다.

- 너무 쉬운 문제(성공률 100%): 이미 다 아는 문제라 배울 게 없어 폐기.

- 너무 어려운 문제(성공률 0%): 성공 시도가 없어 보상 신호가 0이 되므로 폐기.

- 학습 최전선(성공률 50% 부근): 성공과 실패를 오가며 학습 신호가 가장 명확한 문제만 선별해 강화학습 배치에 투입.

문제가 너무 어렵거나 쉬우면 문제 설명의 명세 수준을 다듬어 모델의 학습 가능 경계 안으로 들어오도록 조율했습니다. 이렇게 캘리브레이션된 300개의 문제를 가지고 5번의 회차(총 1,500개 태스크)를 돌리며 모델과 문제 난이도가 함께 계단을 밟아 올라갔습니다.

3. 비동기 환경과 0.2의 안전장치 (DPPO)

에이전트가 코드를 고치고 유닛 테스트를 돌리는 데는 긴 시간이 걸립니다. 연구진은 8대의 NVIDIA B200 중 6대를 롤아웃 수집에, 2대를 가중치 학습에 배치하는 비동기 파이프라인을 구축했습니다.

여기서 시차가 발생합니다. 롤아웃 일꾼이 문제를 풀고 있는 동안 트레이너 쪽 모델은 이미 업데이트되어 버립니다.

이를 통제하기 위해 두 가지 안전장치를 뒀습니다.

- 정책 시차 제약: 문제를 푸는 일꾼과 공부하는 트레이너 간의 버전 차이(Policy Lag)가 1~3스텝 이상 벌어지지 않도록 엄격히 통제했습니다. 일꾼이 너무 뒤처지면 큐가 비워질 때까지 기다려 오래된 버전의 데이터가 섞이는 것을 원천 차단했습니다.

- 비대칭 마스킹: 당시 답을 낸 확률(q)과 현재 모델의 확률(p) 차이(p - q)가 ±0.2(20%p)를 벗어나면 해당 토큰을 학습에서 버립니다. 이미 20%p 이상 실력을 올려둔 행동이라면, 오래된 성공 답안지를 보고 불필요하게 같은 가중치를 중복해서 퍼주는(Over-reinforcement) 사태를 막기 위함입니다.

이 정교한 통제 덕분에 복잡한 KL 패널티나 엔트로피 보너스 없이도 비동기 환경에서 모델의 발산을 깔끔하게 억제할 수 있었습니다.

4. RL 이후 SFT를 붙이면 어떻게 될까? (Consolidation)

연구진은 부록에서 회차가 지나며 사라진 행동(병렬 도구 호출)을 복원하고 점수를 쥐어짜기 위해 이전 체크포인트들의 궤적을 모아 사후 SFT(Consolidation)를 시도했고, 흥미로운 결과가 나왔습니다.

- 점수 상승은 미미: SWE-bench Verified 기준 61.5%에서 62.3%로 +0.8%p 오르는 데 그쳤습니다. 지능의 한계 자체를 뚫어낸 것은 SFT가 아니었습니다.

- 행동 복원과 효율 개선: 대신 1.7%까지 떨어졌던 병렬 도구 호출 빈도를 17.7%로 복원했고, 평균 문제 해결 단계를 53.5스텝에서 36.6스텝으로 크게 단축했습니다.

사후 SFT는 지능을 혁신하는 엔진이라기보다, RL이 흐트러뜨려 놓은 특정 행동 양식을 실무 서빙에 맞게 다듬어주는 사후 패치에 가까웠습니다.

마치며:

RL을 위한 정책 그래디언트 수식은 이미 학계에 잘 정리되어 있습니다. 앞으로는 모델의 작동 경로를 명확하게 정의하는 공학적인 능력이 더 중요해질 것 같습니다.

이 논문이 특별한 점은 작은 모델이 헛돌지 않게 손발을 맞춰주는 인터페이스(하네스) 정의, 비동기 파이프라인에서 오래된 데이터의 중복 강화를 쳐내는 엔지니어링, 그리고 모델이 딛고 올라설 최적의 난이도를 연출해내는 커리큘럼 설계였습니다.

모델을 제대로 돌리려면 전용 하네스는 필수적입니다. 앞으로는 소형 모델들도 전용 하네스와 같이 출시되거나, Liquid AI의 LFM2.5-2.6B나 XHToken의 Spark-X2.5-4B처럼 Codex, Claude Code, OpenClaw, Hermes 등과 통합되어 출시되지 않을까요?

이제 모델을 만들기 위해, 통합된 하네스 환경에 맞춘 강화학습(RL)까지 진행하는 시대가 온 것 같습니다.
