title: "DeepSeek-V4.1-Flash: 극한의 KV 캐시 압축과 Causal Encoder-Decoder로 완성한 효율성"
---

새로운 딥시크 모델인 DeepSeek-V4.1-Flash가 나왔습니다. Qwen3.8-Flash-Next처럼 V4.1-Flash도 Engram이 들어갔습니다. 이제 중국 차세대 모델들에는 Engram이 필수적인 시대가 다가오는 것 같네요. 552B 크기에 Engram이 196B를 차지합니다. A8/16B인데, 뒤에서 V4.1-Flash의 흥미로운 인코더-디코더 구조를 소개드리겠습니다.

얼마 전 V4-Flash 공식 버전이 Post-training만으로 엄청난 성능 향상이 있어서 화제를 모았습니다. V4.1에서도 같은 기법을 썼을텐데, "Post-training에 새로운 알고리즘 혁신은 단 하나도 없었다"고 밝혔습니다.

DeepSeek-V4.1-Flash는 이미지와 텍스트를 처리할 수 있는 멀티모달 모델이며, 여러 작업에서 Opus 5나 GPT-5.6과 비견할 성능을 지닌 MIT 라이선스로 공개된 모델입니다. 이 모델은 철저한 서빙 비용 다이어트와 정교한 데이터 엔지니어링이 핵심인 것 같습니다.

1. 핵심은 엔그램(N-gram)이 아니라 극한의 KV 캐시 압축이다

이번 모델에 N-gram 기반 메모리 모듈인 Engram(196B 파라미터)이 탑재되었지만, 이는 표현력을 보강하는 보조 부품일 뿐 논문의 진짜 주인공이 아닙니다.

진짜 승부처는 초장문 에이전트 환경에서 GPU HBM과 SSD를 폭발시키는 'KV 캐시 메모리'를 극단적으로 깎아낸 데 있습니다.

- 글로벌 KV 캐시 75% 감축: 이전 세대인 V4-Flash 대비 HBM에 상주하는 글로벌 캐시를 토큰당 890 바이트(약 4분의 1)로 줄였습니다. V1(389,120 바이트)과 비교하면 무려 437배 압축입니다.

- SSD 영구 캐시 87.5% 감축: 서버 스토리지에 보관하는 영구 캐시 용량 역시 8분의 1 수준으로 폭락시켰습니다.

- 비결: 레이어 간에 KV와 인덱스를 통째로 빌려 쓰는 CSA2(Compressed Sparse Attention 2), 메인 KV 캐시 FP4 양자화, 그리고 수명이 짧은 로컬 캐시를 SSD에서 아예 치워버린 시스템 설계의 합작품입니다.

2. Causal Encoder-Decoder: 입력을 절반 깊이만 읽고 끝낸다

"인코더-디코더 모델이라니, 옛날 T5처럼 입출력을 반반 나눈 것인가?"라고 오해하기 쉽습니다. 아닙니다. 40층짜리 모델의 깊이(Depth)를 세로로 반 잘라 하위 20층을 인코더, 상위 20층을 디코더로 정의한 구조입니다. 참고로 마이크로소프트가 제안했던 YoCo(You Only Cache Once) 계열의 디코더-디코더 변형 구조를 계승한 것입니다.

핵심은 긴 프롬프트(Prefill)가 들어올 때의 낭비를 막은 방식입니다.

- 상위 20개 레이어 연산 스킵: 긴 문서나 코드 전체를 읽을 때 40층 전체를 통과시키지 않고 하위 20층까지만 돌립니다. 그리고 20번째 층의 결과물에 행렬 곱(Linear Projection) 한 번만 해서, 상위 20개 레이어의 글로벌 KV 캐시를 단숨에 찍어냅니다.

- 파라미터 반토막: 프롬프트를 처리할 때는 단 8B 파라미터만 켜서 연산량을 절반으로 아끼고, 실제로 답변 토큰을 하나씩 생성(Decode)할 때만 1층부터 40층까지 16B를 온전히 켭니다.

3. 1만 번의 재계산 대신 128개만 대충 다시 보기 (SWA Bounded Replay)

슬라이딩 윈도우 어텐션(SWA)은 최근 대화 몇 줄을 정밀하게 보는 필수 기능이지만, 수명이 겨우 몇 분에 불과해 비싼 SSD에 장기 보관하기엔 서버 비용 낭비가 극심했습니다.

그렇다고 SSD에서 캐시를 지워버리면, 나중에 다시 계산할 때 40개 레이어에 누적된 과거 수천 토큰을 처음부터 다시 포워드 연산해야 하는 지옥이 펼쳐집니다.

DeepSeek는 여기서 아주 실용적인 타협을 찾았습니다.

- Bounded Replay: 이론적으로 완벽한 복원을 포기하고, 맨 마지막 128개(창 크기) 토큰만 디코더에 살짝 흘려보내 대충 근사치로 메워버렸습니다.

- 수학적으로는 오차가 발생하지만, 사후 학습 단계에서 이 오차를 미리 맛보게 시뮬레이션해 두었더니 모델 성능이 사실상 단 0.1%도 떨어지지 않았습니다.

- 덕분에 SSD에서 로컬 캐시를 100% 걷어내며 영구 스토리지 비용을 8분의 1로 날려버렸습니다.

4. Post-training의 실체: 마법은 없고 공장만 남았다

최근 중국 모델들의 Post-training 성과의 마법이 궁금했습니다. 그런데 논문에서 공개된 파이프라인은 교과서적인 SFT -> RL -> On-Policy Distillation(OPD) 그대로였습니다.

차이는 알고리즘이 아니라 데이터를 찍어내는 공장에 있었습니다.

- (문제, 환경, 검증기)의 자동화: 모든 합성 태스크를 단순 프롬프트-답변 쌍이 아니라 (문제, 환경, 검증 시스템)이라는 3요소 튜플로 정의했습니다. 그 후 모델 스스로 난이도와 정확성을 평가하며 과제를 무한 복제하도록 만들었습니다.

- 컨테이너 속 멀티 에이전트: 코드 문제를 풀기 위해 설계 에이전트가 깃허브 코드를 분석해 테스트 코드를 짜고, 환경 구축 에이전트가 도커(Docker) 컨테이너를 패키징하며, 다른 에이전트가 문제를 풀면, 감사 에이전트가 해킹이나 오류가 없는지 채점하는 완전 자동화 공장을 구축했습니다.

- 실패 데이터의 역공학: 사내외 직원들이 실제로 업무에서 겪은 수많은 실패 로그와 버그를 긁어모아, 실제 SaaS 도구의 API를 모방한 가상 환경(Mock Tools)을 수만 개 만들고 집중적으로 맞춤형 RL을 돌렸습니다.

마치며:

효율적인 모델 구조(CED, CSA2, FP4)로 KV 캐시를 쥐어짜고, 철저한 학습 데이터 엔지니어링으로 대단한 성과를 달성했습니다.

mHC, Engram 같은 필수적인 기술들에 대한 논문 뿐만이 아니라, 이렇게 모델 전체에 대한 테크니컬 리포트를 계속해서 내주는 딥시크가 정말 고맙네요.

최근 나오는 논문들을 보면, OpenAI나 앤트로픽도 특별한 마법이 있는 게 아닌, 학습 데이터 관리로 뛰어난 성능을 만든 게 아닐까 싶습니다.
