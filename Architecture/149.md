title: "KV-Lingo: 재프리필 없이 1차 선형 행렬로 이종 모델 간 KV 캐시를 번역하는 Apple의 기술"
---

작업 난이도에 따라서, 적합한 모델을 선택하는 모델 라우팅의 중요성이 점점 커지고 있습니다. 그러나 중간에 모델을 바꾸면, 앞서 나눈 대화(KV 캐시)들을 사용할 수 없게 됩니다. 우리는 새 모델에게 기존의 긴 문맥을 처음부터 다시 읽게 만들거나, 앞선 문맥을 모르는 상태로 일을 시켜야 합니다. 이런 이유로 차라리 하나의 뛰어난 대형 모델을 쓰는 것이 더 효율적인 경우도 많았습니다.

Apple 연구진이 공개한 논문 "KV-Lingo: Learning KV-Cache Translators with Distillation"은 단순한 1차 선형 행렬로 모델 간 KV 캐시를 직접 번역해 넘겨주는 기술을 제안합니다.

1. MoA와 라우팅이 마주했던 현실적 벽 (재프리필의 저주)

소형 특화 모델을 여럿 엮는 MoA(Mixture of Agents)나 동적 라우팅은 이론적으로 가장 이상적입니다. 하지만 실무에서 이를 도입하려다 결국 포기하고 거대 모델 하나로 회귀하는 경우가 많았습니다.

- 재프리필(Re-prefill) 병목: 모델 A가 1만 토큰의 문맥을 이미 다 읽었더라도, 모델 B로 전환하는 순간 모델 B는 그 1만 토큰을 처음부터 다시 인코딩해야 합니다. 모델마다 캐시의 구조와 파라미터가 달라 호환되지 않기 때문입니다.
- 제곱 비례의 지연 시간: 문맥을 다시 읽는 연산 비용은 길이에 따라 제곱(O(n^2))으로 증가합니다. 모델을 바꿀 때마다 첫 토큰 생성(TTFT)까지 몇 초씩 화면이 멈추니, 차라리 거대 단일 모델 하나를 쓰는 게 속도도 빠르고 서버비도 덜 드는 역설이 발생했습니다.

2. 복잡한 신경망 대신 단순한 선형 행렬을 쓴 이유

Apple은 타깃 모델이 문맥을 다시 읽는 대신, 출발 모델의 캐시를 타깃 모델 규격으로 즉시 변환하는 'KV-Lingo'를 설계했습니다. 거창한 딥러닝이 아니라 레이어별 토큰 단위의 단순 1차 선형 행렬(Linear map)들만 사용합니다.

- 이미 선형에 가까운 표현 공간: 서로 다른 모델들의 내부 표현(Representation) 기하학 구조를 분석해 보니, 레이어 간 상관관계가 이미 매우 높았습니다. 비선형 MLP를 써봤자 선형 회귀 대비 설명력 차이가 1~7%에 불과했습니다.
- O(n)의 속도: 선형 맵을 적용하면 전체 연산량이 토큰 수에 정비례하는 O(n)으로 끝나기 때문에, 재프리필 연산 대비 비용이 사실상 사라집니다.

3. 수치 맞추기의 함정과 자기 증류(Self-Distillation)

연구진이 밝혀낸 핵심 사실 중 하나는, 캐시의 숫자 오차(MSE)를 줄이는 것만으로는 정상적인 문장이 나오지 않는다는 점입니다.

- 단순 수치 복원의 실패: 1단계에서 행렬 연산으로 캐시 간 수치 차이를 줄여 초기화한 상태(Closed-form)에서는 모델의 다운스트림 성능이 바닥으로 추락합니다.
- 확률 분포 일치: 반드시 2단계 자기 증류를 거쳐, 타깃 모델이 원래 자기 캐시로 낼 다음 단어 확률 분포와 번역된 캐시를 보고 낼 확률 분포 간의 차이(KL Divergence)를 줄여주어야 합니다. 이 과정을 거치자 모델의 실제 생성 성능이 본래 수준으로 온전히 회복되었습니다.

4. 압도적인 속도와 이종 모델 호환성

- 지연 시간 극단적 단축: H100 GPU 환경에서 2k 토큰 기준 첫 토큰 응답 속도가 4.8배 빨라졌고, 32k 장문 문맥에서는 무려 29배나 빨라졌습니다.
- 온디바이스 MoE 가속: Apple M3 Ultra 환경에서 64토큰 기준, 4B Dense 모델이 빠르게 읽은 문맥을 30B MoE 모델로 넘겨 디코딩할 때, 응답 시작 속도가 152ms에서 15.8ms로 9.6배 단축되었습니다.
- 다른 토크나이저 호환: Qwen3-8B와 Mistral-7B처럼 아키텍처와 어휘 사전(Tokenizer)이 완전히 다른 모델 사이에서도 글자 위치(Character offset)를 맞춰 토큰을 정렬하는 방식으로 캐시 번역을 성공시켰습니다.
- 멀티턴 누적 오차 방지: 모델을 번갈아 쓰는 다중 턴 환경에서 매번 전체 대화를 다시 번역하면 오차가 누적되어 무너집니다. 대신 직전 턴에 새로 생성된 구간만 번역해 이어붙이는 방식을 적용해 10턴 이상 연속 전환해도 성능 저하가 없었습니다.

5. 솔직한 한계와 미래

물론 완벽한 무손실은 아닙니다. 학습 범위(16k)를 훌쩍 넘어서는 32k 이상 장문에서는 변환 오차가 누적되어 검색 성능(RULER)이 떨어집니다.

아키텍처와 토크나이저가 완전히 다른 타사 모델 간에는 대형 모델 본래 성능보다는 소형 모델 수준으로 떨어지는 모습을 보이며, 모델 쌍마다 전용 변환 행렬을 미리 학습시켜 둬야 한다는 제약도 있습니다.

하지만 텍스트로 모든 걸 처음부터 다시 설명하느라 발생하던 거대한 장벽을 허물고, 모델 간에 생각(KV 캐시)을 실시간으로 직접 주고받는 통로를 열었다는 점에서 큰 의미가 있습니다.

마치며:

개인적으로 MoA를 자주 이야기하면서 이것이 미래라고 이야기했었지만, KV 캐시 공유의 한계와 프론티어 모델들의 발전 속도를 보고 한계를 느꼈습니다. 그런데 이 논문이 가장 중요한 문제를 완화해 줬습니다.

여러 특화 모델들을 만들면서, 모델들이 공용 캐시 인터페이스를 염두에 두고 함께 훈련할 수 있다면 더 효율적인 에이전트를 만들 수 있을 것 같습니다. 이 분야도 이제 시작하는 분야이며, 빠르게 발전하길 고대합니다!
