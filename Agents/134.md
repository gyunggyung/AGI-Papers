title: "NeMo-DCR: 1T 크기 에이전틱 RL을 위한 비트 단위 델타 압축 가중치 동기화(Refit)"
---

1T 크기의 모델을 강화학습(RL)시킬 때 가장 큰 병목은 학습이 아니라, 학습한 모델을 추론 서버로 옮기는 복사 시간(87.5분)입니다. 강화학습 과정에서 실제로 바뀌는 가중치는 전체의 1%에 불과한데, 그 모든 가중치를 통째로 나르는 것은 심각한 낭비입니다.

NVIDIA 연구진이 발표한 논문 "NeMo-DCR: Bit-Exact Delta-Compressed Refit for Scalable Agentic RL at Trillion-Parameter Scale"은 이 99%의 전송 낭비를 걷어내어 87.5분 걸리던 동기화를 단 2.5분(35배 단축)으로 줄여낸 공학적 해법을 보여줍니다.

1. 99%는 그대로인데 왜 전체를 보내고 있었을까? (feat. LoRA를 안 쓰는 이유)

에이전틱 RL은 전체 시간의 70% 이상을 롤아웃(추론 및 응답 생성)에 쓰기 때문에 학습 서버와 추론 서버를 분리해서 운영합니다. 매 스텝 학습이 끝날 때마다 업데이트된 가중치를 추론 서버로 넘겨줘야(Refit) 다음 배치를 돌릴 수 있죠.

연구진이 BF16 학습 과정을 측정해 보니, 옵티마이저가 한 스텝 업데이트를 해도 반올림 경계를 넘지 못해 실제 저장 비트가 바뀌는 가중치는 전체의 0.6% ~ 1.2%(약 1%) 수준이었습니다.

여기서 "어차피 조금만 바뀔 거면 가벼운 LoRA를 쓰면 되지 않나?"라는 의문이 들 수 있습니다.

이미 RL을 끝내고 공개된 추론 모델을 특정 도메인에 맞게 살짝 교정할 때는 LoRA RL로도 충분합니다. 하지만 SFT만 마친 모델이 처음 RL을 통해 스스로 생각하는 법을 깨우치려면, 모델 전체의 지식을 잘게 쪼개고 재배치하는 풀 파라미터(Full-parameter) RL이 필수적입니다.

NeMo-DCR의 목표는 명확합니다. 모델의 표현력을 깎아먹는 LoRA 제약 없이 풀 파라미터를 그대로 학습하되, 바뀐 위치를 허깅페이스 표준 규격으로 통일해 실제 변한 1%만 쏙 골라 보냄으로써 LoRA 수준의 가벼운 전송을 달성하는 것입니다.

2. 평상시엔 XOR로 쥐어짜고, 문제 생길 땐 Overwrite로 복구한다

바뀐 1%의 새 값을 그대로 보내는 Overwrite 방식도 16비트 전체를 다 실어야 하니 여전히 용량이 큽니다. 연구진은 이를 XOR 연산으로 한 번 더 압축했습니다.

- 평상시 (96% XOR + 4% Overwrite): 가중치가 살짝 변할 때 앞쪽 상위 비트는 그대로 유지됩니다. 이전 값(0x3F01)과 새 값(0x3F02)을 XOR 연산하면 앞자리 14개 비트가 전부 0(0x0003)이 됩니다. 0이 연속되면 압축(zstd) 효율이 극대화되어, 그냥 새 값을 보낼 때보다 용량이 38~40% 더 줄어듭니다. 단, 스케일링 연산 등으로 비트 구조가 변형되는 3~4%의 특수 텐서는 평소에도 안전하게 새 값 그대로(Overwrite) 보냅니다.
- 에러 발생 시 (바뀐 1%만 Overwrite 재전송): XOR은 같은 패킷이 실수로 두 번 적용되면 다시 옛날 값으로 되돌아가는 치명적인 약점(A ^ B ^ B = A)이 있습니다. 전송 도중 추론 서버가 죽어서 옛날 값과 새 값이 반쯤 섞여버리면 XOR로는 복구가 불가능합니다.
- 해결책: 도중에 노드가 죽거나 에러가 나면, 수백 GB의 모델 전체 원본을 다시 보내는 대신 이번 스텝에 바뀌었던 그 1% 항목들에 대해서만 XOR을 버리고 '바뀐 새 값 그대로'를 덮어쓰는 Overwrite 모드로 다시 쏩니다. 몇 번을 덮어써도 무조건 최신 값이 되는 성질을 이용해 엉킨 메모리를 깔끔하게 복구합니다.

3. 릴레이 트리와 파이프라인: 87.5분을 2.5분으로

전송 과정에서도 학습 클러스터와 추론 클러스터를 직접 묶는 집합 통신(NCCL)을 완전히 배제해 한쪽의 장애가 반대편으로 넘어오지 않게 막았습니다.

- 릴레이 트리 전송: 느리고 비싼 리전 간 네트워크(WAN)를 건너 추론 클러스터의 대표(Root) 노드 딱 1곳으로만 패킷을 1회 보냅니다. 이후 대표 노드가 빠른 내부 로컬 망을 통해 나머지 추론 노드들로 트리를 타고 쫙 뿌려줍니다.
- 파이프라인 병렬화: 1T 모델을 다 비교할 때까지 기다리지 않고, 512MB 분량의 버킷이 압축되는 즉시 네트워크로 쏘고 추론 서버는 도착하는 족족 받아서 GPU 메모리에 반영합니다.

결과적으로 120B 모델은 750초에서 22.6초(33배 단축)로, 1T 모델은 87.5분에서 150초(35배 단축)로 동기화 시간이 줄어들었습니다. 5스텝마다 추론 서버를 강제로 죽이는 가혹한 테스트에서도 전체 가중치를 다 보내는 방식과 1비트도 틀림없이 똑같은(Bit-exact) 학습 궤적을 유지했습니다.

마치며:

강화학습 과정에서 모델이 업데이트 될 때마다, 추론 모델을 다시 받아서 띄우는 과정은 큰 병목입니다. 큰 모델일 수록 이 문제가 심각해지죠.

다행히 모델이 출력한 롤아웃을 보상 함수에 맞게 정돈하는 강화학습 과정은 파라미터 변화가 매우 적습니다. 스텝 당 1%의 차이라는 명확한 수치를 찾아서 통신 효율과 압축, 장애 복구까지 모두 해결한 실용적인 논문입니다.
