title: "Reactive Optimizers: 학습 도중 에이전트가 실시간으로 옵티마이저 코드를 수정해 고정 옵티마이저를 압도한 MIT 연구"
---

이번에는 MIT 연구원들이 Claude Opus 5.5에게 학습 중인 모델의 옵티마이저 코드를 실시간으로 직접 고쳐서 성능을 높여달라고 했습니다. 그러자 학습 과정 중에 스스로 학습 상태를 관찰하고 업데이트 규칙을 새로 짜더니, 여러 생성 태스크에서 Muon을 포함한 기존 고정 옵티마이저들을 모두 앞질렀습니다.

학습을 진행하는 도중에 에이전트가 개입해 레이어별 학습률 스케줄, 옵티마이저 알고리즘, 부동소수점 정밀도 등을 실시간으로 뜯어고치며 최적의 학습 경로를 찾아가는 방법론을 소개한 논문 "Reactive Optimizers"입니다.

Claude Opus 5.5에게 딱 두 개의 파이썬 파일, `analysis.py`와 `updater.py`를 읽고 수정할 권한을 줍니다.

가중치나 그래디언트 원본을 그대로 주면 컨텍스트가 터지기 때문에, 에이전트는 먼저 `analysis.py`를 직접 코딩해 연속된 그래디언트 간의 코사인 유사도나 텐서별 노름(Norm) 같은 진단 지표를 스스로 뽑아냅니다. 그리고 이 요약본을 바탕으로 매 스텝 실행되는 가중치 업데이트 코드인 `updater.py`를 실시간으로 새로 작성합니다.

실제 학습 과정에서 Opus 5.5가 보여준 판단들은 꽤 흥미롭습니다.

- `modded-nanogpt`(162M) 학습에서는 토큰 임베딩 값이 약 15인데 `bfloat16` 간격이 0.0625라 작은 업데이트가 반올림으로 증발한다는 사실을 스스로 계산해 내고는, 1,040 스텝부터 그 임베딩 행렬만 `float32` 모멘트와 보상 반올림(Compensated rounding)을 쓰도록 코드를 고쳤습니다.
- 이미지 생성 모델(LightningDiT-XL/1) 학습에서는 AdamW로 시작하더니 어텐션과 MLP를 시작으로 행렬들을 순차적으로 Muon으로 교체하고, 글로벌 스파이크 가드가 너무 자주 작동하자 주범이 timestep embedder 첫 번째 레이어임을 역추적해 가드가 해당 레이어를 무시하도록 코드를 수정했습니다. (무가이던스 FID-50K 5.15 → 4.33 개선, 가이던스 적용 시 2.18 → 1.83 개선)
- CIFAR-10에 고의로 무작위 노이즈 데이터 구간을 4번 섞어 넣자, 처음 두 번은 정확도가 50~66%p씩 폭락하니 스스로 '최근 정상 배치보다 Loss가 비정상적으로 높은 배치는 업데이트를 차단하는 게이트(Batch Gate)'를 코딩해 손실을 0(+0.7%p)으로 완벽히 막아냈습니다.

에이전트가 추론하느라 학습이 멈추는 병목을 막기 위해, 에이전트가 생각하는 동안에는 기존 코드로 학습을 계속 돌리고 수십 스텝 뒤에 새 코드를 자연스럽게 교체(Swap-in)하는 비동기 방식을 썼습니다.

덕분에 전체 학습 시간 오버헤드는 1~14% 수준에 불과했고, 약 $510(74 H100-hours)가 드는 LightningDiT 학습 동안 에이전트가 100번 결정을 내리는 데 쓴 Opus 5.5 API 비용은 고작 $6.42였습니다. GPU 비용에 비하면 Opus 5.5도 쌉니다.

에이전트가 스스로 온라인 A-B-A 테스트를 돌려보고 학습률을 결정하거나, 2025년에 나온 최신 학습률 감쇠 논문을 직접 인용하며 쿨다운 시점을 앞당기는 모습을 보면, 이제 프론티어 모델의 LLM에 대한 이해도가 어지간한 사람 수준을 넘어섰다는 생각이 듭니다.

이전 글에서 GPT-6 Astra가 Qwen3.5-0.8B의 가중치를 수정하는 것도, 이번에 Claude Opus 5.5가 NanoGPT의 옵티마이저를 실시간으로 수정하는 것도 모두 프론티어 모델들의 성능이 극적으로 높아지고, 다들 재귀적 자가개선(RSI)에 도전하기 때문에 가능한 일인 것 같습니다.

물론 이 논문도 100M~수백M 규모의 모델들을 가지고 진행하는 PoC 수준의 연구입니다. 그래도 멋진 가능성을 보여줬기에, 이런 연구들이 앞으로 중대형 LLM에도 적용된다면 어떤 결과가 나올지 기대되네요.
