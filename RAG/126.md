기본적인 RAG가 대화 기록을 관리하는 에이전트들 보다 뛰어나다고 합니다. Mem0, MemOS, Zep처럼 대화가 들어올 때마다 LLM을 시켜서 내용을 요약하고, 지식 그래프를 그리고, 옛날 기억을 수정하거나 지우는 방식은 원본 내용을 훼손시켜 오히려 성능을 깎아먹고 있다고 합니다.

시안교통대, 상하이교통대 등 공동 연구진이 발표한 논문 "Is Complex Agentic Memory Always Needed? Naive RAG Is Stronger Than We Thought"는 가장 기본적인 일반 RAG만 제대로 세팅해서 써도 최신 에이전트 메모리 12개를 전부 이긴다는 실험 결과를 보여줬습니다.

1. 어설픈 요약과 수정이 오히려 기억을 망친다

Mem0 같은 시스템은 새로운 대화가 들어오면 기존 기억을 덮어쓰거나(UPDATE) 지우는(DELETE) 기능을 핵심으로 내세웁니다. 하지만 Mem0의 쓰기 결정 46만 건을 전수 조사해 보니, 실제로 텍스트를 유의미하게 고치는 비율은 1.34% ~ 1.90%에 불과했습니다.

심지어 Mem0에서 수정과 삭제 기능을 강제로 꺼버리고 무조건 단순 추가(ADD)만 하도록 바꿨더니, LoCoMo 벤치마크 정답률이 67.36%에서 69.42%로 오히려 올라갔습니다.

이유는 단순합니다. 저장할 때 LLM이 개입해서 원본을 요약하거나 짧은 사실(Atomic fact)로 쪼개버리면, 사건의 시간 순서나 인과관계 같은 중요한 맥락이 영구적으로 날아갑니다. 사건 현장의 사진 원본을 버리고, 목격자의 짧은 메모만 남기는 격입니다.

저장할 때 한 번 날아간 정보는 나중에 에이전트가 아무리 똑똑하게 재검색 루프를 돌아도 복구할 수 없습니다. 요즘 LLM의 추론 능력이 워낙 좋아서, 날것의 원본 대화만 그대로 찾아서 던져주면 "옛날엔 이랬는데 나중에 저렇게 바뀌었구나"를 즉석에서 알아서 계산해 냅니다.

2. 기존 논문들의 왜곡과 제대로 된 RAG 레시피

그렇다면 왜 그동안 논문들에서는 일반 RAG의 성능이 낮게 나왔을까요? 기존 에이전트 메모리 논문 14개를 뜯어보니, 비교 대상인 RAG의 검색 개수를 단 1~3개로 묶어두거나 청크를 4,096 토큰으로 무식하게 크게 자르고, 리랭커(Reranker)도 아예 빼버리는 식으로 성능을 왜곡하고 있었습니다.

연구진이 구성한 RAW-RAG는 아주 간단하고 정석적인 파이프라인입니다.

- 원본 보존: 요약이나 가공을 일절 하지 않고 원본 대화를 256토큰 단위로 잘라 임베딩합니다.
- 2단계 검색: 임베딩 유사도로 128개를 넓게 뽑은 뒤, 리랭커로 정밀하게 다시 채점해 상위 15개만 추립니다.
- 문맥 복원: 잘린 문장을 복구하기 위해 최종 뽑힌 15개 조각은 원래 대화 턴(메시지) 전체로 늘려서 LLM에게 보여줍니다.

특히 오픈웨이트인 Qwen3-Embedding-4B와 Qwen3-Reranker-4B 조합을 썼을 때 성능이 가장 높았습니다. OpenAI와 Cohere의 상용 API 모델보다 오픈웨이트 모델이 더 나은 성능을 발휘한다는 게 좋네요.

3. 결과: 83배 빠르고 정확도는 1위

4대 메모리 벤치마크에서 Mem0, MemOS, EverMemOS, Memora 등 12개 최신 시스템을 모아놓고 비교했습니다.

- 정확도 석권: 7개의 벤치마크-모델 세팅 중 6개에서 단순한 RAW-RAG가 1위를 차지했습니다.
- 속도와 비용: 100만 토큰 분량의 대화를 메모리에 넣을 때 Memora는 27시간, EMem은 18.2시간, Mem0는 3.9시간이 걸렸습니다. 반면 임베딩만 하는 RAW-RAG는 단 0.3시간(약 20분) 만에 끝났습니다. 무려 83배 빠르고 저장 시 LLM 호출 비용은 0원입니다.

오히려 RAW-RAG에 원자적 사실 추출, 요약본 추가, 그래프 확장을 억지로 얹어봤더니, 시간만 수 시간 더 걸리고 정확도는 5.8%p ~ 19.6%p나 떨어졌습니다.

마치며:

이 논문은 저장 시점의 원본 보존 효과를 증명하기 위해 검색을 1회성 고정 RAG로 통제했습니다. 그래서 논문에서도 짧게 언급된 ReFind처럼, 원본 대화 로그를 그대로 둔 상태에서 에이전트가 직접 Bash의 grep처럼 키워드 검색이나 문맥 확장 툴을 반복 호출하며 탐색하는 에이전틱 방식과는 비교하지 않았습니다.

원본을 훼손하지 않으면서 에이전트가 직접 탐색 도구를 다루는 방식은 기본 RAG보다도 더 뛰어날 확률이 높습니다. 또한 유저의 전반적인 성향을 파악하는 프로필 태스크(PersonaMem-v2)에서는 프로필 추출 기능이 있는 시스템이 더 나은 모습을 보이기도 했습니다.

그럼에도 이 논문은 좋은 교훈을 줍니다. 기억을 저장할 때 LLM으로 어설프게 요약하고 수정하느라 원본을 망치지 말라는 것입니다. 화려한 메모리 프레임워크는 오히려 원본을 무너뜨리니, 올바르게 원본을 찾는 작업에 집중해야겠습니다.
