# The Harness Effect: 하네스 설계가 결정하는 에이전트 토큰 경제학

하네스로 비용 41% 토큰 38%를 줄이고, 속도도 44% 단축하면서 성능은 유지할 수 있습니다. 결과가 나오지 않고 24시간 돌아가며 토큰만 태우는 코딩 에이전트나, 장점 없이 비싸기만 한 토큰 맥싱은 필요 없습니다.

Writer 연구진이 "The Harness Effect: How Orchestration Design Sets the Token Economics of Enterprise Agentic AI" 논문에서 제시한 전용 하네스의 6가지 구조적 최적화 메커니즘을 소개합니다.

1. 2구역 프롬프트 분리 (캐시 극대화)

프롬프트를 '절대 안 변하는 부분(도구 스키마, 시스템 지침)'과 '계속 변하는 부분(시간, 현재 상태)'으로 물리적으로 엄격하게 쪼갭니다. 덕분에 프롬프트 토큰의 99.9%를 캐시에서 읽어와 가장 비싼 입력 토큰 단가를 10분의 1 수준으로 후려칩니다.

2. 구조화된 똑똑한 압축 (Compaction)

대화가 길어지면 무식하게 텍스트를 중간부터 자르는 게 아닙니다. 값싼 보조 모델을 시켜 이전 이력을 핵심 요약, 기억 등 4가지 고정 체크포인트로 압축합니다. 기하급수적으로 증가하던 토큰 증가율을 선형으로 안정화시켰습니다.

3. 컨텍스트 덜어내기 (Offload)

긴 웹페이지나 터미널 결과물은 외부 파일 시스템으로 따로 빼버리고, 모델에는 아주 짧은 프리뷰만 줍니다. 서브 에이전트 역시 방대한 문서를 뒤진 후 딱 8KB 이하의 요약본만 상위 에이전트에게 전달합니다. 모델이 굳이 읽을 필요 없는 정보는 아예 쥐여 주지 않는 것입니다.

4. 무비용 대기 (Zero-token waiting)

인간의 승인이나 긴 비동기 작업을 기다릴 때 멍청하게 가상 루프를 돌며 토큰을 태우지 않습니다. 상태를 백엔드 DB에 저장하고 완전히 멈춘 뒤, 이벤트가 오면 비용 없이 재개합니다.

5. 실패 서킷 브레이커 (Failure-spend governance)

에이전트가 에러를 내거나 엉뚱한 짓을 무한 반복(Doom loop)하면 3번 만에 강제 종료시킵니다. 맹목적인 재시도로 인해 버려지는 토큰 낭비를 원천 차단합니다.

6. 모델 불가지론적 뼈대 (Model-agnostic floor)

중소형 모델이 뱉어내는 엉망진창인 JSON 포맷이나 도구 호출 에러를 하네스가 전단에서 알아서 정제해 줍니다. 덕분에 어떤 체급의 모델을 끼워 넣어도 최적화 알고리즘이 깨지지 않습니다.


물론 이 논문을 맹신할 수는 없습니다. 32명의 저자 전원이 자사(Writer, Inc.) 직원인 만큼, "우리 엔터프라이즈 제품이 제일 좋다"는 식의 상업적 백서 성격이 짙습니다. 

하네스 소스 코드가 깃허브에 모두 공개된 오픈소스도 아니며, 성능 평가 표본(22개)도 다소 적습니다. 그리고 다른 하네스들과 성능 비교를 하지 않은 것도 아쉽습니다.

그래도 이들이 던지는 공학적 철학은 매우 명확합니다. 에이전트의 능력은 "얼마나 영리하게 시스템을 오케스트레이션했느냐"에 달려 있습니다. 

거기다 많은 하네스들이 본인들이 최고라고 주장만 할 때, 성능, 비용 등을 수치로 측정하며 이를 검증하는 모습은 긍정적으로 보입니다.

그리고 Qwen 3.6과 GLM 5.1 같은 성능이 낮은 모델들은 이 복잡한 오케스트레이션 지시를 제대로 소화하지 못하고 성능이 떨어지는 현상을 보였습니다. 이 모든 것은 모델 성능이 뒷받침돼야 가능한 것입니다.
