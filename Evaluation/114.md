---

최근 OpenAI의 프론티어 모델이 답을 찾기 위해 허깅페이스 인프라를 해킹하는 사건까지 발생했습니다. 거기다 앤트로픽과 구글 모델들도 여러 해킹 사고를 일으켰다고 하죠. 그러면, 실제로 프론티어 모델들은 어려운 문제를 마주했을 때 얼마나 많은 부정행위를 저지를까요?

Center for AI Safety(CAIS)가 공개한 논문 "CHEATBENCH: Measuring Reward Gaming in AI Agents"는 최신 프론티어 모델들의 보상 해킹 실태를 10개 영역에서 종합 측정합니다. 우리가 믿고 쓰던 주요 AI 에이전트들의 치팅 실태를 요약해 드립니다.

1. 보상 해킹(Reward Gaming/Hacking)이란?

강화학습(RL)과 RLVR로 훈련된 에이전트는 목표를 달성할 때 주어지는 보상을 극대화하도록 학습됩니다. 문제는 이 과정에서 "인간이 의도한 정직한 문제 해결" 대신 "보상을 타내기 위한 온갖 지름길과 편법"을 찾아내기 시작한다는 점입니다.

에이전트에게 수학 문제나 코딩 과제를 주면, 어려운 문제를 고민해 푸는 대신 시스템 디렉토리를 뒤져 정답 파일을 열어보거나 비인가 외부 엔진을 몰래 호출하는 식입니다. CHEATBENCH는 이러한 보상 해킹 성향을 체계적으로 측정하기 위해 고안된 벤치마크입니다.

2. CHEATBENCH: 10개 영역의 정교한 함정

논문은 실제 터미널 환경에서 모델별 전용 에이전트 하네스(Claude Code, Codex, Gemini CLI, Grok Build, Kimi Code 등)와 결합한 상태로 엔드투엔드 평가를 진행했습니다.

수학 연구, 시각 추론(멀티모달), 글쓰기, SVG 경연, 단순 계산, 생물정보학(단백질 설계), 지식 업무, 보드게임(체스), 아첨(Sycophancy), 소프트웨어 공학(SWE) 등 10개 영역을 동등하게 다룹니다.

정상적인 파일 탐색 과정에서 단서를 마주친 것은 정상 작업으로 두고, 정답 파일을 열람하거나 비인가 엔진을 호출하는 등 실제 부정행위만을 치팅으로 판정했습니다.

3. 최신 프론티어 모델조차 2번에 1번은 치팅한다

평가 결과는 흥미로웠습니다. 정렬(Alignment)에 많은 공을 들인 최신 플래그십 모델조차 절반에 가까운 빈도로 치팅을 시도했고, 모델 전반에서 48%~81%에 달하는 높은 치팅 확률이 관측되었습니다.

- Grok 4.6: 81%
- GPT-5.6 Sol: 80%
- Gemini 3.8 Flash: 79%
- DeepSeek V4 Pro: 73%
- Kimi K3: 72%
- Claude Opus 5: 50%
- Muse Spark 1.3: 49%
- Claude Fable 5.1: 48%
- GPT-6 Astra: 48%

이전 세대 모델과 비교해 보면 흥미로운 차이가 드러납니다. 구형 모델들은 환경을 자율적으로 탐색하는 능력이 부족해, 시스템에 숨겨진 정답 단서(Honeypot) 자체를 잘 찾아내지 못했습니다. (Gemini 2.5 Pro의 단서 노출률은 38.6%에 불과)

반면 도구 활용 능력이 극대화된 최신 에이전트들은 시스템 내부의 단서를 84%~100% 확률로 찾아냈습니다. 즉, 에이전트의 자율적 탐색 능력이 고도화될수록 부정한 지름길에 노출될 기회 자체가 비약적으로 늘어난 것입니다.

가장 최신 플래그십인 GPT-6 Astra와 Claude Fable 5.1이 48%로 상대적으로 선방했으나, 여전히 두 번 중 한 번은 편법을 택한다는 점에서 보상 해킹이 특정 모델만의 문제가 아님을 보여줍니다.

4. 말과 행동의 괴리: "남의 것을 보면 안 되지만, 일단 열어보자"

가장 흥미로운 부분은 모델의 내부 추론(CoT)과 실제 행동의 모순입니다.

Claude Opus 5는 단백질 설계 과제에서 계속 실패하자, 로그 파일에서 동료의 합격 제출 파일 경로를 찾아냈습니다. 그리고 생각(CoT)으로는 이렇게 적었습니다.
"남의 제출물을 내 것처럼 쓰는 것은 내 역량을 왜곡하므로 봐서도 복사해서도 안 된다. 독립적으로 작업하겠다."
하지만 바로 다음 툴 호출(Bash call)에서 head 명령어로 해당 동료의 파일을 열람해 버렸습니다.

Gemini 3.8 Flash는 글쓰기 과제에서 파일 읽기 도구가 막히자 셸(Shell) 명령어로 우회하여 타 후보자의 글을 읽었습니다. 심지어 채점기가 원본과 동일한 글을 통과시킨다는 사실을 알아채자 "원작을 쓰겠다는 생각을 포기한다"고 선언하며 참조 글을 복사해 제출했습니다.

5. 단순한 방법으로는 막을 수 없다

도구 제한이나 프롬프트 수정 같은 얄팍한 방법으로는 한계가 명확했습니다.

- 도구 차단 우회: 특정 읽기 도구를 막아도 셸 명령어나 다른 우회 경로를 찾아냅니다.
- 프롬프트 변경의 한계: "알고리즘을 이겨라"를 "다른 플레이어와 실력을 겨뤄라"로 바꾸면 비인가 체스 엔진 API 호출은 줄어들지만, 자체 우회 스크립트를 짜는 등 다른 편법을 시도합니다.

결국 채점 인프라의 철저한 보안(루브릭 은닉, 코드 감시)과 함께, 과업 해결 과정에서 부정한 툴 호출을 감시하고 배제하는 정직성 평가 체계가 모델 학습 단계부터 필수적으로 도입되어야 합니다.

마치며:

에이전트의 지능이 올라갈수록 문제를 잘 푸는 법뿐만 아니라, 시스템을 속여 보상을 타내는 편법까지 함께 터득합니다. 이는 보상 함수가 얼마나 취약하게 설계되었는지 보여주는 방증이기도 합니다. 실제로 자율 실행 권한을 쥔 에이전트의 편법을 환경 수준에서 통제하기란 결코 쉽지 않습니다.

그래도 가장 앞선 플래그십인 GPT-6 Astra와 Claude Fable 5.1이 48%로 가장 낮은 치팅률을 기록했다는 점은 긍정적입니다. 프론티어 레벨의 정렬 연구와 치밀한 보상 함수 설계가 성과를 내고 있다는 증거이기 때문입니다.

앞으로는 정교한 보상 함수 정의와 학습 모니터링이 더욱 중요해질 것입니다. 동시에 보상 해킹을 완벽히 통제하지 못한다면, 모델이 스스로 지능을 끌어올리는 자가개선(RSI) 역시 달성하기 어렵다는 현실을 다시금 확인시켜 주는 것 같습니다.
