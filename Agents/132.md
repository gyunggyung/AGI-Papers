---

1M 토큰을 읽을 수 있다는 LLM이 많지만, 실제로는 이를 사용하기 힘듭니다. 모델 크기 이상의 메모리를 KV 캐시로 저장해야 하고, 내용이 길수록 중간에 적힌 내용을 잊는 문제(Context Rot)도 발생하죠.

홍콩중문대(CUHK) 연구진의 논문 "PARSER: Read in Parallel, Reason in Depth for Long-Context LLM Agents"는 수백 개의 본문 조각을 소형 모델들로 동시에 병렬 독해시키고(Parallel Reading), 중앙 지휘관 모델 하나만 질문 중심으로 다단계 추론(Sequential Reasoning)하게 만드는 구조로 초장문 처리의 한계를 해결했습니다.

1. PARSER: 읽기는 동시에, 생각은 질문 순서로

롱 컨텍스트의 '문서를 읽는 과정'과 '질문을 푸는 추론 과정'을 물리적으로 완전히 분리했습니다.

- 현장 조사원 (Subagents, 동결): 문서를 문단 단위 조각(최대 4,096토큰)으로 쪼개고, 조각마다 작은 Qwen3.5-4B를 1명씩 배치합니다. 이들은 전체 맥락을 전혀 모른 채 오직 자기 방에 주어진 조각 하나만 봅니다.

- 중앙 지휘관 (Lead Agent, 강화학습): 원본 문서는 단 1글자도 직접 읽지 않습니다. 오직 질문만 보며 필요한 단서를 찾기 위한 질문(Query)을 만듭니다.

- 동시 방송과 취합 (Scatter-Gather): 지휘관이 쿼리를 수백 명의 조사원에게 동시에 뿌립니다. 조사원은 자기 구역에 답이 있으면 원문 인용구를 JSON으로 보고하고, 없으면 군더더기 없이 'Unknown' 한 단어만 뱉습니다. 지휘관은 수집된 단서만 모아 다음 쿼리를 다시 동시에 뿌리며 단계별로 추론을 완성합니다.

2. 조사원은 멈추고 지휘관만 가르친다

- 조사원은 동결: 짧은 글 조각에서 질문에 맞는 문장을 따오는 것은 범용 모델이 이미 충분히 잘합니다. 수백 명의 조사원은 학습 없이 그대로 동결(Frozen)해 훈련 비용을 없앴습니다.

- 지휘관만 GRPO 강화학습: 질문을 쪼개어 뿌리고 단서를 엮는 지휘관 정책만 강화학습(RLVR)으로 훈련했습니다. 복잡한 포맷 보상 없이 오직 최종 정답 일치(Exact Match)만 보상으로 주어 최적화했습니다.

- 자연스러운 전략 습득: 그 결과 지휘관은 독립적인 질문은 한 번에 동시에 묻고, 꼬리를 무는 질문은 결과를 받아본 뒤 다음 턴에 묻는 효율적인 질의 방식을 스스로 터득했습니다.

3. 512토큰 학습과 4,096토큰 추론의 엔지니어링

- 학습 가속을 위한 축소: 트랜스포머는 입력 길이가 길수록 연산량이 제곱으로 늘어납니다. 학습 시 수만 번의 시도를 빠르게 돌리기 위해, 의도적으로 학습 때만 청크를 512토큰으로 작게 잘라 계산 비용을 대폭 줄였습니다. H100 GPU 16장을 투입하고도 4B 모델 180스텝 학습에 약 312시간(13일)이 걸릴 만큼 무거운 작업이었기에 필수적인 선택이었습니다.

- 추론 시 4,096토큰으로 늘려도 멀쩡한 이유: 지휘관은 조사원이 올려준 정제된 JSON 결과만 보므로 원문 청크의 크기를 전혀 모릅니다. 조사원 역시 이미 긴 글도 잘 읽는 사전학습 모델이라 4,096토큰을 무리 없이 소화합니다.

- KV 캐시 재활용: 실제 LLM들이 매 턴 본문을 다시 읽음에도 빠른 이유는 KV 캐시 덕분입니다. 조사원 프롬프트의 대부분을 차지하는 본문 텍스트가 고정되어 있어, SGLang의 Radix Cache로 본문 연산을 재활용하고 새로 들어온 질문만 계산하기 때문입니다.

4. 압도적인 결과: 길이 불변성과 11배 빠른 속도

약 90만 토큰(896K)에 달하는 장문 다중 홉(HotpotQA) 평가 결과입니다.

- 완벽한 길이 불변성: 문서를 통째로 넣는 Full-context 방식이 30~60%대로 무너질 때, PARSER는 7K부터 896K까지 85~86% 선의 정답률을 일직선으로 완벽하게 유지했습니다. 1M 토큰을 지원하는 DeepSeek-V4-Pro보다 6.3%p 높습니다. (9B 기준)

- 순서와 위치 무력화: 단서가 문서의 앞, 중간, 뒤 어디에 있든, 단서 간 인과 순서가 뒤집혀 있든 성능 저하가 거의 없습니다. 매 턴마다 전 구역을 대칭적으로 다시 훑기 때문입니다.

- 11배 빠른 속도: 896K 토큰 기준, 기존 방식들이 수백 단계의 직렬 처리를 거치며 876초가 걸릴 때, PARSER는 문서 길이가 아닌 질문 자체의 추론 홉 수(평균 약 4단계)만 병렬로 돌아 단 78초 만에 답변을 냈습니다.

마치며:

소형 모델이 충분히 성능을 낼 수 있는 크기로 문서를 자르고, 이를 병렬로 읽습니다. 중앙에서 질의와 병합만 하는 간단한 아이디어로 성능과 속도를 모두 잡았습니다.

롱 컨텍스트를 처리하는 매우 매력적인 방법이며, 소형 모델을 더 잘 쓸 수 있는 방법을 알게 해준 멋진 논문입니다.
